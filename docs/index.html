What this project actually found

Readiness does not depend on the model

/readyz returns 200 even with no model loaded, because the popularity fallback can serve traffic. Gating readiness on the model would pull the whole service out during a bad rollout, which is exactly backwards.

Degraded is a state, not an outage

The serving tier reports degraded separately from healthy, so a fallback is visible in metrics instead of looking like normal traffic.

Promotion is gated on a shadow run

A new model serves shadow traffic and is compared before it is promoted, with automated rollback if it regresses. Deploying on a green build alone tests the build, not the model.

The ANN index was benchmarked, not assumed

Recall and latency are measured across index configurations, because an approximate index that quietly loses recall looks exactly like a fast one.
